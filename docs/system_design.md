# 離線系統設計與範圍

規則查閱基準日：2026-11-15；TAIFEX 2027 日曆於 2026-11-16 更新。此設計支援研究與紙上驗證，不提供下單路徑。

## 模組

| 模組 | 檔案 | 職責 |
|---|---|---|
| TAIFEX 歷史匯入 | `download_txo.py` | 下載日行情 CSV，保留原始來源列並匯入 SQLite。 |
| 交易日／時段規則 | `market_time.py` | 依簽入的 TAIFEX 日曆檢查日期、日夜盤時間及週三／週五到期排程。 |
| 歷史資料稽核 | `quality_check.py` | 以唯讀 snapshot 核對交易日與時段、契約、數值及官方抽樣，並輸出有追溯證據的 JSON 與摘要 Markdown。 |
| 定價與訊號診斷 | `txo_engine.py` | Black-76、IV 反解、成本、同步報價檢查、靜態界限和策略候選。 |
| 紙上帳本 | `paper.py` | 限定有限風險 option basket 的記憶體內 pending／fill／close／cancel 與風控。 |
| 合約規則 | `docs/txo_contract_rules.md` | TAIFEX 契約、交易、結算、稅費、保證金與部位限制快照。 |

T1 保留每日 OHLC、結算價、成交量、未平倉量與最後最佳買賣價，沒有日內報價序列、深度、事件時間或配對期貨。`readiness` 會明確回報這些欄位缺口。T2 在一致的唯讀 SQLite snapshot 上檢查資料，並比較 TAIFEX 官方抽樣；不修改 SQLite 行情。原始資料與含列級來源證據的完整 JSON 報告被 Git 忽略，摘要 Markdown 報告受 Git 追蹤。

## 單位、定價與候選訊號

- TXO 權利金以指數點報價，契約乘數為 50 元／點；履約價、期貨報價與期交成本需使用同一到期結算基準。
- Black-76 以遠期價格、履約價、年化利率、到期年分數及波動率計價；IV 使用二分法，拒絕到期、價格界外及不可識別輸入。
- 期交稅按每口計算後四捨五入至整數元。TXO 買賣權利金稅率和券商費用由成本快照提供，生效日超過 30 日會拒絕分析。
- 平價多合成期貨空頭的鎖定現金流為 `(F_bid - K) × 50`；反向部位為 `(K - F_ask) × 50`。期貨腿限定乘數 50 元的 MTX／等值契約，不能以乘數 200 元的 TX 報價代入。成本快照須含進場期交稅率與到期交割費、期交稅準備；進場稅依成交價、乘數逐口四捨五入。套利現金流模型要求借款與投資利率非負，且借款利率不低於投資利率；Black-76 定價利率仍可為負。依鎖定現金流正負使用借款或投資折現率，再扣各腿 ask／bid、稅費及期貨費用。
- 每筆 snapshot 目前要求選擇權與期貨報價都有正口數的 bid 和 ask。TAIFEX 行情的單邊空簿屬合法狀態，但這版會拒絕整份 snapshot；需等 feed adapter 支援缺邊價格與逐方向深度後才能涵蓋。
- 長箱以折現履約價差對照四腿成交價及費用；短箱反向計算。兩者均有同到期、價格同步、頂層口數和成本限制。
- 垂直單調性／價差界限與蝶式檢查輸出靜態套利診斷。跨期 IV 只輸出方向性觀察項，不列入套利訊號。
- 期限檢查：同買賣權、相鄰到期日在同一 log-moneyness 的總變異 iv²·T 必須不減；違反者寫入 `surface_diagnostics`。以 mid IV 計算且只在遠月曲線範圍內線性內插，不外插、不列入套利訊號。
- 所有候選都只代表輸入快照下的數學診斷；不能代表行情可成交、沒有腿風險或可獲利。

## 紙上帳本與風控

`MockBroker` 僅支援箱型、垂直價差和蝶式組合；接受明確的 timestamp、received_at、source、sequence、size、交易時段、費率、結算時點及結算識別。每張訂單凍結輸入快照；同一契約與交易所時間的價格、深度或正規化時段不能改寫，接收時間、來源名稱或序號不會增加可用量。序號衝突拒單不會發布新的報價事件。輸入 source 標籤仍未經簽章驗證。

成交只按買方 ask、賣方 bid 原子填滿；超過 5 秒報價壽命或到達到期結算時點即過期，並釋放尚未成交的深度與風險額度。每個合法單調模擬事件都會掃除過期委託。價格由帳本根據買賣方向取值，呼叫端不能傳入自訂成交價。取消 pending 委託會釋放額度；已成交深度不會重複使用。

送單及成交事件需位於 quote 指定的 TAIFEX 交易時段；新同契約報價事件會讓使用舊報價的 pending 委託過期，模擬時鐘跨盤時也會清除該時段所有 pending 委託。日曆的盤後交易日由實際開盤日及其後下一交易日計算，涵蓋 2025-11-14 至 2027-12-31，並含 2027 春節前夜盤歸屬規則。到期日只按週三／週五排程、簽入的順延資料及日曆休市日推算，不能證明特定契約已實際掛牌；未來公告、特別停夜盤及日曆涵蓋範圍外都需更新日曆後再用。

壓力損失在設定的結算指數範圍內檢查 0、上限與各履約價，並保守假設範圍上限稅額及每腿交割費準備套用到所有腿。範圍上限須高於所有履約價。此數字是範圍內壓力值，不是 TAIFEX 保證金、法定最大損失或範圍外上限。日損失預算會扣除當日已實現損益與未平倉壓力額度；實際結算按價內履約口數計算履約稅與交割費。同到期未結部位可重播完全相同的已登記結算事件。首次結算事件可晚於目前模擬時鐘到達，但 timestamp 必須落在契約到期日，損益歸屬該事件日期，時鐘維持單調。未記錄結算回報接收時間。結算來源標籤會留存，但來源真實性不驗證。

結算指數超出進場壓力範圍時仍按傳入結算值計算實際 paper 損益並釋放持倉額度，同時在結算與 audit log 標記 breach；這項變更防止預估範圍外的真實結算被錯誤拒絕，不代表輸入結算值已驗證。

依日期觸發的 kill switch 只取消該模擬日 pending 委託；直接呼叫 `trip_kill_switch()` 會取消所有 pending 並鎖定整個執行個體。它不會替使用者平倉或呼叫外部服務。帳本是單程序記憶體狀態，不可當成多使用者或正式環境持倉系統。

## 可重現指令

```powershell
uv run --python 3.12 quality_check.py --start 2025-11-14 --end 2026-11-13
uv run --python 3.12 txo_engine.py readiness --db data/txo.sqlite3 --output reports/system_readiness.json
uv run --python 3.12 txo_engine.py analyze --snapshot examples/snapshot.example.json --output reports/example_analysis.json
uv run --python 3.12 examples/paper_demo.py
uv run --python 3.12 pytest -q
```

`examples/snapshot.example.json` 與 `examples/paper_demo.py` 都是合成輸入，沒有使用網路或真實交易資料。Paper demo 的 JSON 報告包含輸入委託、合成成交、結算結果和 audit log。
